# ERP Transaction Manual

## Purpose

This document provides high-level guidance about ERP transaction handling without providing live transaction execution instructions.

## Transaction Guidance

Before starting any ERP transaction:

1. Identify the relevant business process.
2. Confirm the ERP module.
3. Confirm the user's functional role.
4. Verify that the user is authorized to perform the activity.
5. Review the organization's approved transaction procedure.
6. Follow the configured workflow and approval requirements.

## Transaction Examples

### Purchase Order

A purchase order generally records an approved request to purchase goods or services from a supplier.

Typical functional flow:

1. Review the approved purchasing requirement.
2. Confirm supplier and purchasing information.
3. Create or review the purchase order according to the organization's procedure.
4. Complete required approvals.
5. Proceed with the applicable purchasing process.

### Sales Order

A sales order generally records a customer's request for goods or services.

Typical functional flow:

1. Review the customer requirement.
2. Confirm customer and order information.
3. Create or review the sales order according to the organization's procedure.
4. Complete required validations and approvals.
5. Continue with delivery and billing processes.

## Guidance-Only Boundary

The ERP Functional Support Assistant must not:

- Execute transactions.
- Access live ERP systems.
- Modify ERP records.
- Change ERP configuration.
- Bypass approval workflows.
- Provide instructions that imply it has performed an ERP transaction.

When a user requests transaction execution, explain that the assistant provides guidance only and direct the user to perform the transaction through their authorized ERP interface or contact the appropriate ERP support team.
